> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans task-by-task. Track completed evidence below; do not infer completion from a partial diff.

**Goal:** Implement default evidence-bound acceptance and non-blocking usage visibility, and prepare a reproducible real-business comparison without claiming the multi-day pilot has run.

**Architecture:** Extend the existing Team runner, SQLite stores, acceptance checks and usage pipeline. Enable the new behavior per team; preserve legacy behavior until an owner opts in and resolves old limits. Use host-issued execution metadata and one usage projection, not a second billing ledger.

**Tech stack:** Python 3.12, FastAPI, SQLite, plain JavaScript dashboard, existing Python/Node test harness.

## Integration interfaces and file ownership

1. **Acceptance backend:** server/team_acceptance.py, team_runner.py, team_store.py, task_store.py and new team_quality.py; new acceptance tests. Owns migration, readiness, contract lifecycle and quality policy. Does not edit main.py, team_api.py or dashboard files.
2. **Usage backend:** usage_store.py, usage_parsers.py, usage_index.py, aux_engine.py, turn_context.py, main.py and new team_usage.py; new usage tests. Does not edit team_runner.py, team_acceptance.py, team_store.py, task_store.py, team_api.py or dashboard files.
3. **Baseline tests:** existing test_team_gate_factory_0207.py, test_team_sequential_steps.py, test_team_acceptance_0209.py only. Production path validation belongs to acceptance backend. No gate weakening.
4. **Coordinator:** team_api.py, dashboard/teams.js, i18n files, route_table fixture, pilot files, documentation, release notes and integration tests. Reviews returned work and verifies whole branch.

Shared contracts:

- `TeamRunner.quality` exposes `policy(team_id) -> dict`, `set_policy(team_id, body) -> dict`, `template(team_id) -> dict | None`, `set_template(team_id, body) -> dict`. Policy has `enabled`, `cost_behavior='observe_only'`, `limit_migration='retain'|'observe'`, optional `reference_usd`. Template uses `version` / body `expected_version` for CAS.
- `TeamRunner.decide_acceptance` keeps its current arguments and adds optional keyword `contract_version`, `output_manifest_hash`, `decision_key`. The acceptance view supplies all three input keys (new decision_key generated by client) and `completion_valid`.
- `team_usage.task_usage(team_id, task_id) -> dict` and `team_usage.team_usage(team_id) -> dict` return read-only summaries with `attempts`, `requests`, `tokens_in`, `tokens_out`, `money` provenance, `coverage`, role breakdown and `cost_behavior='observe_only'`. Missing attribution is exposed, never guessed.
- Usage context set in main._team_engine_for includes team_id/task_id/step_id/turn_id/attempt/role/job_revision; tokens and bills remain owned by provider record events. The existing runner execution tables are references, not added bills.
- GET task/team views combine acceptance, quality policy/template and usage summaries. New APIs stay owner-authenticated and brain/team/task checked.

## Review focus

- Crash between the two SQLite stores must never dispatch a quality job without a contract; test submission and recovery boundaries.
- Two browser tabs confirming different output revisions must never accept a newer unseen result; test idempotency and stale rejection.
- Retry with real new usage must not be deduplicated as replay; final CLI summary plus detailed log must not be counted twice.
- Existing default per-task/day caps must not silently defeat observe-only, while explicit administrative ceilings and permissions remain intact.
- A subscription provider returning an API-equivalent dollar value must not inflate cash spend; unknown observations must remain visible.
