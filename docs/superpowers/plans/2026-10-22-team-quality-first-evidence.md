# Quality-first Team candidate: evidence and release boundary

Original analysis base: `d6781404` (0.281.0); candidate rebased onto latest main `1134f3d9` (0.282.0). Candidate: `codex/team-quality-first`, reserved 0.283.0, draft PR #791. Original dirty checkout preserved; implementation is in the managed worktree. Automated tests use scratch state and fake engines. No production deployment, live provider execution or business pilot result is implied.

## Delivered scope

- Per-team opt-in policy and compare-and-swap acceptance templates. New jobs snapshot owner obligations before claim; missing templates bind owner confirmation to the actual saved final message.
- Contract versions, host-computed manifests and current-validity checks. Stale decisions and known objective failures cannot be broadly accepted. Policy disablement retains bound contracts.
- Durable owner decision intents, task application markers, deterministic repair steps and deduplicated decision messages. Courtesy completion pulses are at-most-once and may be omitted by a crash after claiming; they are not an external exactly-once delivery guarantee.
- Observe-only monetary references. An explicit one-time legacy-limit choice preserves unknown historical intent. Observe migrates old saving presets for owner obligations while later explicit caps, admin ceilings, provider quotas and autonomous-work bounds remain binding.
- Usage over the existing event/index pipeline, with host execution identity, actual API attempts, retained error usage, request/turn distinction, unknown fields and separate cash/estimate/subscription equivalents.
- Owner-scoped APIs and vi/en dashboard controls, version-bound decision retries, template obligation preservation, historical-unverified labeling and mobile layout checks.
- Twenty-pair dry-run harness with independent arms, preserved failures and blank owner reviews. Read-only trace export retains version/provenance evidence without claiming current output validity or inventing a reconciled bill.

## Verification record

- Baseline isolation/path/timing changes: three original test files pass. Gates remain enabled.

- Final targeted regression: **10/10 files pass** (60s), including 43 contract, 17 usage, seven API, two checker, five pilot and one trace case. Review regressions rerun per affected surface: owner API, usage, runner, queue, authority, acceptance matrix, Team JS, pilot and trace export. Final exact output is retained in the task's `exports/team-quality-first` evidence directory and CI on the PR.
- Real headless Edge checks pass in vi/en at 390px with all details expanded; screenshots were inspected. The fixture overrides drawer positioning only so full-page screenshots include all cards; production panel styles remain in use.
- Initial reservation CI failed `test_version_khop_changelog.py` because the release heading was embedded in the format preamble. The heading and bilingual actual release notes are corrected; the version check is rerun before pushing implementation.
- Fresh-context review found legacy HTTP snapshot coercion, cross-store completion recovery, unknown-token zero coercion and early completed lifecycle status. Each received a failing regression before its fix. Review also caused quality command checks to fail closed pending isolated execution.

## Outstanding release/pilot work

This is an opt-in candidate, not completion of the entire multi-week program. It does not enable quality-first by default or deploy to a user's server. Real pilot adapter integration, frozen business inputs/independent answer keys, owner-score ingestion/comparative reporting, 7–10 days of observation and a tested complete-state restore drill remain prerequisites to business rollout. The dry-run report intentionally leaves quality improvement and accepted-result cash cost undefined.

Checker isolation and fuller provider/role attribution are explicit follow-up work. New usage summaries do not provide runtime/wait durations. No real pilot conclusion or broad all-provider completeness claim can be drawn from these tests.
